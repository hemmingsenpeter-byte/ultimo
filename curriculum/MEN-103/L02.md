# MEN-103 / L02 — Task decomposition

**Draft — independent academic and qualified subject review pending.** Outcome: Compare and distinguish task decomposition in the context of motivation and procrastination.

## Core teaching

Task decomposition turns a broad outcome into smaller, observable units. It is useful when an objective is ambiguous, difficult to begin or dependent on prerequisites. Distinguish deliverables (what must exist), actions (what you do), dependencies (what must be available first), and acceptance criteria (what counts as good enough). A list of activities is not a plan unless it connects to the outcome. For example, 'research' is vague; 'identify three comparable options and record their dates and evidence' is observable.

Decomposition can be top-down, starting with required outputs and working backwards, or bottom-up, starting with a feasible first step and learning what the task demands. In uncertain work, an exploratory task can reveal missing information before the rest is planned. Avoid breaking a task into so many tiny actions that planning becomes another avoidance activity. Also distinguish controllable tasks from requests dependent on others. A well-designed plan may reveal that the deadline, scope or available resources are incompatible.

The decomposition worksheet below is a practical teaching method. Research on procrastination includes motivational and self-regulatory interventions, but that does not establish the effectiveness of every task-breakdown technique. Evaluate whether this particular decomposition makes progress easier without creating unnecessary administration. It is appropriate to stop, ask for help, renegotiate or abandon a low-value objective rather than endlessly making smaller steps.

## Framework

**Outcome–deliverable–action–check**

Write one outcome. Identify two to four deliverables that are necessary. Draw arrows for dependencies. For the earliest feasible deliverable, specify a small first action using a verb and object. Add an acceptance criterion and a review point. Re-estimate after the first attempt.

Text diagram: outcome → required deliverables → prerequisites → next feasible action → check → adjust. For uncertain tasks, include a discovery step rather than guessing every detail.

## Worked example

A fictional community group wants a venue proposal. Outcome: select a suitable room within the agreed budget and access requirements. Deliverables: requirements list, comparison of three venues, recommendation. Dependencies: the requirements must be agreed before the comparison can be meaningful. First action: draft a five-row table of date, capacity, accessibility, location and maximum cost. Acceptance: each field has either an agreed requirement or a marked open question. The learner can proceed with the draft without knowing every venue price. If the cost ceiling is missing, they request clarification rather than fabricating it.

### Contrasting case

A familiar recurring task that takes two minutes may not need a dependency diagram. Conversely, a specialised task may require training or authorisation before any meaningful first action. Decomposition cannot make a hazardous or unqualified task safe.

## Guided practice

### Build a dependency plan

Scenario: a fictional learner must prepare a ten-minute presentation comparing two transport options. Available: two short reports. Missing: the audience's preferred format. Define the outcome, three deliverables, dependencies, an immediate action and an acceptance criterion.

### Worked solution

Outcome: a decision-ready comparison. Deliverables: extract common criteria; compare both options using the same measures; prepare a concise explanation with uncertainties. First action: read the headings of both reports and write the candidate criteria. Ask the audience about format in parallel. Acceptance: both options use the same relevant criteria and all missing figures are flagged. The format question need not block preliminary extraction. Feedback: remove tasks that do not support the outcome and identify which uncertainties actually block progress.

Attempt the task before checking the worked solution. Identify one justified correction, then repeat using an equivalent fictional case. The criterion is quality of reasoning, not personal performance or symptom change.

## Independent transfer

Take a different fictional objective and create a dependency map with at least one missing prerequisite. Specify one action that can be taken safely now and one that must wait. Review whether the plan is proportional to the task.
