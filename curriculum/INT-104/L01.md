# INT-104 / L01 — Hypotheses

**Draft — independent review pending.** Outcome: Explain hypotheses in the context of scientific reasoning.

## Orientation and retrieval

Distinguish a prediction from a guarantee. Imagine that a new filing convention appears to save time: what observation would count against that impression?

## Core teaching

A hypothesis proposes a relationship or explanation that can be examined using evidence. A prediction describes what we would expect to observe if the hypothesis and its supporting assumptions hold. Operationalisation translates an abstract concept into a measurement procedure. For example, efficiency may be defined as minutes needed to find a specified file, with accuracy measured separately. A useful test distinguishes the proposed explanation from at least one alternative. Exploratory work can generate hypotheses after observing data, but a subsequent confirmatory test should avoid treating the same observations as independent confirmation. A result inconsistent with a prediction may challenge the hypothesis, measurement or auxiliary assumptions. One observation rarely settles a complex scientific theory; the appropriate response is to investigate the discrepancy, not simply discard it or rationalise it away.

## Framework

Write a question, a candidate explanation, an observable prediction, a measurement rule and a possible contrary result. Add a competing hypothesis and describe what observation would distinguish them. This is an instructional design checklist, not the only legitimate scientific method. Keep exploratory and confirmatory stages explicitly labelled.

## Worked example

A fictional office hypothesises that consistent file names reduce retrieval time. Prediction: on a fixed set of equivalent search tasks, the median retrieval time is lower under the new naming convention without an increase in incorrect files. Define start and stop times before the test. A competing explanation is that staff are already familiar with the test documents; use unfamiliar equivalent documents and balance practice order.

### Contrasting case

‘The new system is better because people like it’ is too vague to test as written. It may become testable by defining satisfaction and retrieval accuracy separately; neither measure alone captures every aspect of quality.

## Guided practice

Turn ‘visual instructions are clearer’ into a protocol. Model: predict fewer assembly errors for a paper puzzle using illustrated rather than text-only instructions; use comparable puzzles, record errors before giving feedback, and specify that no difference or more errors would weaken the prediction. Consider prior experience as a rival explanation.

Attempt the task before reading the model; compare your reasoning, correct one concrete gap and retry.

## Independent transfer

Design a paper-only experiment about an everyday work process. Record your prediction, units, comparison and contrary outcome before generating or inspecting simulated results.
