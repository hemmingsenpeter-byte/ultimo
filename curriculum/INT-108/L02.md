# INT-108 / L02 — Reference classes

**Draft — independent review pending.** Outcome: Compare and distinguish reference classes in the context of forecasting and decisions.

## Orientation and retrieval

Recall the forecast question's defined outcome. Before analysing a project in detail, ask what happened to similar projects in the past.

## Core teaching

A reference class is a set of comparable cases used to estimate an outcome distribution or base rate. The outside view begins with past outcomes; the inside view focuses on the particular plan and its circumstances. They complement each other when differences are justified. The challenge is selecting a class that is similar in the mechanisms that matter while large enough to be informative. A broad class may obscure important differences; a narrow class may be noisy or opportunistically chosen. Include unsuccessful and incomplete cases where relevant, handle missing data explicitly and avoid selecting the comparison group because it produces a preferred answer. A base rate is a starting point, not a binding verdict about a specific project.

## Framework

Define the target event; state the selection criteria before inspecting results; compute the comparable base rate or distribution; identify reasons the case differs; document any adjustment and test a second plausible class. If no useful class exists, acknowledge uncertainty.

## Worked example

Of 20 comparable fictional software upgrades, 12 finished by their original deadline, giving a 60% observed completion rate. A narrower group with the same supplier contains 4 successes in 5. That 80% rate is potentially relevant but based on few cases. A forecast should consider both, explain differences and avoid mechanically adopting the more optimistic number.

### Contrasting case

A database of only completed projects omits cancelled projects. It cannot estimate on-time delivery among all initiated projects without accounting for selection.

## Guided practice

Given Class A: 30 successes out of 50 projects; Class B: 7 out of 10 similar-scope projects, compare 60% and 70%. Identify an inclusion criterion, one source of missing data and a reason not to average the two if Class B is contained within A.

Attempt before reading the model; compare your reasoning and correct a specific gap. Record assumptions and ask what would change your conclusion.
